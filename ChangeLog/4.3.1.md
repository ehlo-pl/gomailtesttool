# Version 4.3.1

## New Features

### sendmail: optional Wikipedia article as the body

With the new `--body-source wikipedia` option, `sendmail` (smtp, jmap, ews,
msgraph, gmail) run without any body fills the message with a random featured
article from English Wikipedia. "Without any body" means no `--body`,
`--bodyhtml` or `--template`, whether set by flag, env var or config file.
The default, `--body-source static`, keeps the previous behaviour: the
one-line placeholder text is sent and Wikipedia is not contacted.

- **Categories**: by default articles come from 12 FA-Class WikiProject
  categories: Computer science, Computing, Technology, Engineering, Systems,
  Internet, Telecommunications, Cryptography, Robotics, Statistics, Chemistry
  and Astronomy (about 230 articles). A category is picked at random, then an
  article within it. `--body-categories` (env `<PROTOCOL>BODYCATEGORIES`,
  config key `body-categories`) replaces the list; the `Category:` prefix is
  optional.
- **A new article on every run**: before picking, the action's default result
  logs (`_<tool>_sendmail_*.csv` / `.jsonl` in the temp directory, all dates)
  are read. Articles whose title already appears in a logged subject are
  skipped. When every article in the categories has been used, one is
  repeated and a warning is logged. This relies on no subject being given,
  because the subject is where the title is recorded.
- The message gets a plain-text and an HTML part. Each starts with the
  original placeholder line, a link to the article and the CC BY-SA 4.0
  attribution.
- When no subject is given, the subject is set to `Wikipedia: <article title>`.
  An explicit subject is kept.
- The fetch is best effort, with a 15 s timeout. If it fails (for example with
  no Internet access), a warning is logged and the static placeholder body is
  sent. The request honours `HTTP(S)_PROXY`, and for msgraph also `--proxy`.
- `--body-source wikipedia|static` (default `static`) is also available as an
  env var (`SMTPBODYSOURCE`, `JMAPBODYSOURCE`, `EWSBODYSOURCE`, `MSGRAPHBODYSOURCE`,
  `GMAILBODYSOURCE`) and as the config file key `body-source`.
- msgraph `sendmail --mimebase64` and the `draft`, `sendinvite` and `serve`
  paths are unchanged.

## Bug Fixes

### JMAP: sendmail failed on Stalwart and other strict servers

- **Sending identity**: every `EmailSubmission` now carries the `identityId`
  that RFC 8621 requires. The identity is looked up with `Identity/get` and
  matched to the sender in this order: exact address, then a `*@domain`
  wildcard, then the account's only identity. When several identities exist
  and none match, the command fails and lists the available identities. This
  fixes `invalidProperties (emailId, identityId): emailId and identityId
  properties are required`.
- **Mailbox**: the message is always created in a real mailbox (Drafts, or Sent
  when there is no Drafts mailbox), because RFC 8621 does not allow an empty
  `mailboxIds`. After submission the draft is destroyed
  (`onSuccessDestroyEmail`). With `--save-to-sent` it is moved to Sent instead
  and its `$draft` keyword is cleared (`onSuccessUpdateEmail`).
- **Envelope**: Cc and Bcc recipients are included in the SMTP envelope for the
  `Email/set` path. Previously they were missing.
- **Error reporting**: per-object rejections (`notCreated`) from `Email/set`,
  `Email/import` and `EmailSubmission/set` are now reported with the server's
  reason, such as `invalidProperties (mailboxIds)` or `forbiddenFrom`.
  Previously a rejected submission could be reported as success. A failure to
  create the message is reported before the submission error it causes.

### SMTP: `SMTPBODY` env var was ignored

The `SMTPBODY` env var was named in the `--body` help text but was never
bound. It now sets the body.

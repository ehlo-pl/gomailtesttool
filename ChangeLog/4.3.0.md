# Version 4.3.0

## New Features

### TestMailFlow: new `testmailflow` tool

A new binary, built from `apps/TestMailFlow`, tests mail flow end to end: it
sends small probe messages over SMTP or Microsoft Graph and verifies over
Microsoft Graph, the Gmail API, IMAP or POP3 that they arrive in the target
mailbox. Sender and checked mailbox can be different accounts and systems.

- Many named flows in one YAML file; endpoints use the flag names of
  `gomailtest <protocol>`, with `${ENV}` references for secrets.
- Per flow: probe interval, check schedule (default: after 5 minutes, then a
  further 2.5, 5, 10 and 15 minutes) and a "late" threshold.
- Probe states `delivered`, `late`, `lost`, `send_failed`; delivery latency is
  taken from the delivered message's `Received` header; hop count and
  SPF / DKIM / DMARC verdicts are recorded.
- A mailbox that cannot be checked is reported separately and never counted
  as lost mail. Pending probes survive a restart.
- Native Windows service: `testmailflow service install|uninstall|start|stop|status`
  (delayed automatic start, restart on failure). `testmailflow run` for the
  foreground, systemd or other supervisors.
- Reporting: `status` (monitoring-friendly exit codes), `report` (text, CSV,
  JSON), Windows Event Log events on state changes, optional HTTP `/healthz`
  and Prometheus `/metrics`.
- `once` sends a single probe per flow and waits for the result; `validate
  --connect` checks the configuration and credentials.

See [apps/TestMailFlow/README.md](../apps/TestMailFlow/README.md).

### Protocols: exported senders

`internal/common/send` defines a protocol-neutral `Sender` (Send / Close) for
submitting a ready-made RFC 5322 message, implemented by `smtp` and `msgraph`
(`OpenSender`). Unlike the `sendmail` actions the senders print nothing and
write no CSV rows. Existing `gomailtest` commands are unchanged.

## Build

- `make build-tmf` / `make build-all`, `build-all.ps1 -MailFlow`.
- Release ZIPs include `testmailflow`; pull-request validation builds it and
  runs its unit tests together with the send layer tests.
- `golang.org/x/sys` is now a direct dependency (Windows service and Event Log).

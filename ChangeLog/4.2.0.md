# Version 4.2.0

## New Features

### DMARC analyzer: new `dmarcanalyzer` tool

A new binary, built from `apps/DMARCanalyzer`, collects DMARC aggregate (rua)
report e-mails from a mailbox over Microsoft Graph, the Gmail API, IMAP or POP3,
saves them as `.eml`, extracts the zip / gzip / xml reports into a local SQLite
database (pure Go, no CGO) and summarizes them by day, week, month, quarter or
year as text, Markdown, CSV, JSON or a self-contained HTML page.

- `collect <protocol>` is incremental: message keys are remembered and the
  default window starts at the previous run minus a configurable overlap.
- `--delete-after --yes` removes server copies only of messages whose report
  was stored.
- `extract` also accepts `.eml` files from `gomailtest <protocol> exportmessages`
  and loose `.xml/.xml.gz/.zip` report files; duplicate reports are stored once.
- `report` shows pass rates, DKIM/SPF alignment, dispositions, per-domain
  policy, reporters, top sources, actionable failures with hints, override
  reasons, policy changes and period-over-period trend; optional PTR lookup.
- `run <protocol>` combines collect and report for scheduled runs.

See [apps/DMARCanalyzer/README.md](../apps/DMARCanalyzer/README.md).

### Protocols: exported fetch sessions

`internal/common/fetch` defines a protocol-neutral `Session` (Fetch / Delete /
Close) implemented by `imap`, `pop3`, `msgraph` and `gmail`
(`OpenFetchSession`). Unlike `exportmessages`, the sessions support date
ranges, follow paging (Graph `@odata.nextLink`, Gmail `pageToken`), skip
already-known messages before download and request least-privilege scopes.
Existing `gomailtest` commands are unchanged.

## Build

- `make build-dmarc` / `make build-all`, `build-all.ps1 -Dmarc`.
- Release ZIPs include `dmarcanalyzer`; pull-request validation builds it and
  runs the DMARC analyzer and protocol unit tests.
- New dependency: `modernc.org/sqlite` (pure Go SQLite).

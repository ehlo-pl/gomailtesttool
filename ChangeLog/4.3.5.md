# Version 4.3.5

## New Features

### warmingup: Windows support (`apps/warmingup`)

- Native Windows service: `warmingup service install|uninstall|start|stop|status`,
  with `--user` for the service account (password from `WARMUPSERVICEPASSWORD`).
- As a service it writes daily logs to `<datadir>\logs`; start, stop and holds also
  go to the Application event log.
- `service install` limits the data directory to SYSTEM, Administrators and the
  service account.
- New global setting `warmingup: envfile:` for `${NAME}` values, on all systems.
  The process environment takes precedence.

### warmingup: usage guide

- `apps/warmingup/USAGE.md`: walkthrough with example configuration and output, a
  table of mailboxes to check and a per-mailbox checklist.

## Changes

- warmingup on Windows: the default data directory is `%ProgramData%\warmingup`
  (was per user). Move an existing database from `%LOCALAPPDATA%\warmingup`, or
  pass `--datadir`.
- warmingup: a relative `datadir` is relative to the config file, not to the
  working directory. The sample config no longer sets `datadir`.

## Internal

- The Windows service and event log code moved from testmailflow to
  `internal/common/svc` and `internal/common/eventlog`, and its daily log writer
  to `internal/common/logger`. testmailflow behaves as before; only the "Windows
  only" error shown on other systems is worded differently.

# Version 4.1.0

## New Features

### EWS: `freebusy` action — Free/Busy availability test (closes #109)

A new `ews freebusy` subcommand performs a dedicated Free/Busy test via the EWS
`GetUserAvailability` API. Unlike the existing `getschedule` (merged view,
defaults to 24 h) and `findtimeslot` (computes free slots, single recipient),
`freebusy` is a purpose-built **PASS/FAIL test** designed to verify that a
service account can successfully query calendar availability for one or more
mailboxes.

**Key features:**
- Required parameters `--mailbox`, `--start`, and `--end` enforce explicit input.
- Optional `--to` accepts additional mailboxes in a single request (comma-separated).
- `--timezone` (IANA name, default `UTC`) controls display and interpretation of times.
- `--interval` (5–60 minutes, default `30`) sets the merged free/busy slot granularity.
- Per-mailbox PASS/FAIL outcome with event counts, status breakdown
  (Free/Busy/Tentative/OOF/WorkingElsewhere), and up to 5 sample events.
- Normalized status mapping (`NoData` fallback for unknown EWS `BusyType` values).
- Comprehensive error handling with actionable diagnostics
  (`ErrorCalendarNoFreeBusyAccess`, `ErrorMailboxNotFound`, auth failures, etc.).
- CSV log columns: `Action`, `Status`, `Server`, `Port`, `Username`, `Mailbox`,
  `Start`, `End`, `Timezone`, `Interval_Minutes`, `Event_Count`,
  `Response_Time_ms`, `Error`.

**New environment variables:**
- `EWSTIMEZONE` — `--timezone`
- `EWSINTERVAL` — `--interval`

**Example:**
```powershell
gomailtest ews freebusy --host mail.example.com \
    --username "CORP\serviceaccount" --password "secret" \
    --mailbox target@example.com \
    --start "2026-08-01T08:00:00Z" --end "2026-08-01T17:00:00Z" \
    --timezone "Europe/Warsaw"
```

# Version 4.3.4

## New Features

### warmingup: domain warm-up service (`apps/warmingup`)

A Linux-oriented service that warms up sending domains with slowly growing
volume through your own mail server. See `apps/warmingup/README.md`.

- One configuration file per warmed domain: campaign start and end, business
  hours (or none), holidays, ramp and rates, targets and thresholds. By
  default 1 message on day 1, growing over 30 days to 3 per business hour plus
  1-2 outside.
- Content from the `--body-source` sources (Wikipedia, RFC, poetry), as a
  short excerpt that is never sent twice.
- Target mailboxes over IMAP (including Outlook.com sign-in with
  `warmingup auth`) and JMAP: records inbox or junk placement, headers and
  latency, then marks the message read and moves it out of junk.
- Bounce mailbox parsing, automatic hold of a target or domain on bad results,
  and `plan`, `status`, `report`, `validate`, `once` and `resume` commands.

## Bug Fixes

- IMAP `XOAUTH2` authentication sent the `OAUTHBEARER` mechanism, which is a
  different SASL mechanism. It now sends `XOAUTH2`.
- SMTP: without authentication the client greeted with an empty name before
  `MAIL FROM`. It now repeats the EHLO name.

## Internal

- Endpoint parsing, `${ENV}` expansion, secret masking and durations moved to
  `internal/common/endpoint`, shared by testmailflow and warmingup.
- New `internal/common/mailbox` API (find in inbox or junk, mark read, move to
  inbox), implemented by imap and jmap. The SMTP library sender accepts an
  `ehloname` setting.
